0x05 数据命令
=============

.. container:: doc-status

   **第一版本**\ 　历史数据（含运动结束后的运动记录）与今日数据；即时测量见 :doc:`点测命令 <0x11-measurement>`。

   * - Value

* 多字节整数**大端**\ 。时间戳 4B：1970 起**墙上时钟秒**\ （与设备显示时间一致，不做时区换算）。
* 无效值：1B ``FF``\ ，2B ``FFFF``\ ；有符号 2B ``8000``\ ；经纬度 4B ``7FFFFFFF``\ 。
* 单位：温度 0.01 ℃，血糖 0.1 mmol/L，卡路里 0.1 kcal，经纬度 1e-7°。**体温**\ 在手表侧校准、补偿后入库，SDK 直接展示。

**Key 分区（每段预留 32 个功能位）**\ ：同步请求 ``0x00``\ ～``0x1F``\ 、数据返回 ``0x20``\ ～``0x3F``\ （**数据 Key = 同步 Key + ``0x20``**\ ）、同步控制 ``0x40``\ ～``0x5F``\ 、今日 ``0x60``\ ～``0x7F``\ 、运动详情 ``0x80``\ ～``0x9F``\ 。各 Key 含义与 Value 布局见 :ref:`规则 <cmd-05-section-2>`。

.. _cmd-05-section-2:

规则
----

* **同步请求 ``0x00``～``0x0A``**\ ：手机发起，Value **空**\ ；**数据 Key = 同步 Key + ``0x20``**\ 。一次交互：手表 **``0x40``** → 数据 **``0x21``～``0x2A``**\ （Key 升序，同 Key 可多帧）→ **``0x41``**\ ；手机存盘后 **``0x42``**\ （空）。**全量**\ 同步；去重：健康「类型+时间戳」，运动摘要 **``sport_id``**\ 。``0x40`` 条数 = 请求时快照，作进度分母。
* **数据返回 ``0x21``～``0x2A``**\ ：Value = **单条长 1B + 条数 2B + 记录 × 条数**\ （同类型多条可在一帧；一帧放不下可多帧，每帧自带帧头）。无类型/index/版本。记录末尾可扩展；不兼容换新数据 Key。
* **同步控制 ``0x40``～``0x42``**\ ：号段 ``0x40``\ ～``0x5F``\ ；第 2 节表排在数据 Key 后面仅为阅读顺序。**报文顺序**\ ：``0x40`` → ``0x21``\ ～``0x2A`` → ``0x41``\ ，最后手机 ``0x42``\ 。
* **今日 ``0x60``～``0x63``**\ ：首页当天累计，与历史同步并行；**``0x62``** 定下推策略（默认开/全天/1 分钟，手表不存盘），**``0x60``/``0x61``** 同 23B。
* **运动详情 ``0x80``/``0x81``**\ （**不是**\ 健康类型同步）：主同步只带 **``0x2A`` 摘要**\ ；采样另拉。摘要 **``detail_flags`` bit0 = 1** 才可发 **``0x80``**\ （**sport_id 4B**\ ）。手表 **``0x81``** 回详情：**分帧 L2** 或 **流式字节**\ （见 :ref:`具体命令 <cmd-05-section-3>` ``0x81`` 各行，固件择一）；手机**无**\ 详情确认 Key。
* **互斥 / 超时**\ ：同时只一场历史同步，或一场 **``0x80``** 运动详情；忙时 ``0x41``=``02`` 或 ``0x81`` ``count=0``\ 。今日通道不计历史约 10s 超时。无取消同步 Key。
* 第 2 节按 Key 排序（历史同步报文顺序仍是 ``0x40`` → 数据 → ``0x41``\ ）；「具体的命令」为完整 L2 hex。示例 2026-10-12 08:30:00 = ``6A CC 9A 88``\ 。
