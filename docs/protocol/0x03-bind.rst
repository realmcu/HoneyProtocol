二、消息定义
------------------------------------------------------------------------------------------------------------------------

.. list-table::
   :header-rows: 1
   :widths: auto

   * - Key
     - 名称
     - 方向
     - Value
   * - 0x01
     - 绑定请求
     - 手机 → 设备
     - 用户 ID 32B
   * - 0x02
     - 绑定返回
     - 设备 → 手机
     - 结果 1B：00 成功，01 超时，02 用户拒绝
   * - 0x03
     - 登录请求
     - 手机 → 设备
     - 用户 ID 32B
   * - 0x04
     - 登录返回
     - 设备 → 手机
     - 结果 1B：00 成功，01 ID 不一致（包括设备从未绑定过）
   * - 0x05
     - 解除绑定
     - 手机 → 设备
     - 1B 预留，填 00；没有 L2 回应，只有 L1 ACK
   * - 0x06
     - 超级绑定
     - 手机 → 设备
     - 用户 ID 32B + Super key 32B
   * - 0x07
     - 超级绑定返回
     - 设备 → 手机
     - 结果 1B：00 成功，01 超时，02 Super key 校验失败，03 电量低

* 用户 ID：32 字节 ASCII，不足 32 字节时在末尾补 0x00。SDK 默认生成 32 位十六进制字符串。
* 绑定需要用户在手表上确认：设备收到绑定请求后弹出确认界面，用户确认回 00，拒绝回 02，超时回 01。
* 已被其他用户绑定的手表：用户在手表上确认后，覆盖原来的绑定（待固件确认）。
* 解除绑定：App 发出后直接断开，不等 L2 回应。设备收到后清除绑定的用户 ID。
* 超级绑定：固件端需要，协议保留。从返回值看它也会失败（超时、Super key 校验失败、电量低），不是"一定成功"的绑定。用途、触发时机、Super key 的来源待问固件，确认后再定 SDK 是否把它放进连接流程。

三、连接流程
------------------------------------------------------------------------------------------------------------------------

1. 每次连接都先发 0x03 登录（用户 ID）。
2. 0x04 = 00：登录成功，进入初始化（设置手机系统、对时、读功能列表、读设备信息）。
3. 0x04 = 01（ID 不一致或从未绑定）：发 0x01 绑定，手表弹出确认界面，等待用户操作。
4. 0x02 = 00：用户确认，绑定成功，进入初始化。
5. 0x02 = 01 超时 / 02 用户拒绝：断开连接，提示用户。

* 每次连接都先登录，登录成功才进入初始化；不存在"连上但未登录"的可用状态。
* 绑定请求的回包等待时间要大于手表的确认等待时间。手表最多等多久待问固件，SDK 的等待时间 = 手表等待时间 + 5 秒。

四、与老协议（HL_Private_Protocol.md 第 3 章）的差异
------------------------------------------------------------------------------------------------------------------------

* 去掉老协议的 0x07 / 0x08 确认绑定：新协议的绑定本身就要用户在手表上确认，登录回应也不再有"02 需要确认绑定"。
* 去掉老协议的 0x06 芯片类型：主控平台已在设置命令 0x30 设备信息里。
* 0x06 / 0x07 改为超级绑定。
* 绑定回应新增"02 用户拒绝"，和超时区分开。

五、待确认（固件）
------------------------------------------------------------------------------------------------------------------------

.. list-table::
   :header-rows: 1
   :widths: auto

   * - 编号
     - 事项
   * - 1
     - 手表确认绑定最多等多久（SDK 等待时间 = 该值 + 5 秒）
   * - 2
     - 已被其他用户绑定的手表，用户确认后是否直接覆盖原绑定
   * - 3
     - 超级绑定：什么场景用（普通绑定失败后的兜底，还是售后 / 产测）；是否跳过手表确认；Super key 由谁生成、App 从哪里拿；返回"01 超时"指什么超时
   * - 4
     - 绑定返回新增"02 用户拒绝"，固件是否能区分拒绝和超时

六、表格说明
------------------------------------------------------------------------------------------------------------------------

* "具体的命令"一列为完整的 L2 数据（十六进制，大端序），可直接对照抓包。按字段分颜色：

03 00 灰色：L2 Header 04 红色加粗：Key 00 01 灰色：v-length 00 绿色加粗：Value
