0x02 设置命令
=============

.. _cmd-02-section-1:

命令格式
--------

以下为 L2 层命令格式，不含 L1 帧头。

.. list-table::
   :header-rows: 1
   :widths: 18 10 18 54
   :class: protocol-table command-format columns-4

   * - 字段
     - 长度
     - 取值
     - 说明
   * - L2 Header
     - 2B
     - 02 00
     - Command = 0x02 设置命令，Version = 0，Reserve = 0
   * - Key
     - 1B
     - 见下方表格 KeyID
     - 每个功能一个 key
   * - v-length
     - 2B
     - 操作码 + 操作数据的总长度
     - 包含操作码这 1 个字节
   * - 操作码
     - 1B
     - 见 :ref:`操作码 <cmd-02-section-2>`
     - Value 的第 1 个字节
   * - 操作数据
     - 可变
     - 见下方表格
     - 每个功能各自定义

.. list-table:: 示例：设置亮度 80%
   :header-rows: 1
   :widths: auto
   :class: packet-table

   * - L2 Header
     - Key
     - v-length
     - 操作码
     - 操作数据
   * - ``02 00``
     - ``20``
     - ``00 02``
     - ``00``
     - ``50``

* 多字节整数一律大端序
* 所有字段按字节对齐，不做 bit 压缩（功能列表、消息提醒开关这类位图除外）

.. _cmd-02-section-2:

操作码
------

.. list-table::
   :header-rows: 1
   :widths: auto
   :class: protocol-table columns-4

   * - 操作码
     - 方向
     - 操作数据
     - 说明
   * - 0x00 设置
     - 手机 → 设备
     - 设置值
     - 普通设置用，整体覆盖；没有回应
   * - 0x01 读取
     - 手机 → 设备
     - 一般为无
     - 个别 key 需要带参数，如 0x61 间隔提醒带类型 1B，0x91 通讯录带起始槽号 1B
   * - 0x02 读取回应
     - 设备 → 手机
     - 当前值
     - 读取的唯一回应；设备不支持、读不出时不回应，手机按超时处理
   * - 0x03 通知
     - 设备 → 手机
     - 当前值；列表型为变更类型 + 单条记录
     - 设备上的设置有变更就上报，不区分是手机设置的还是手表上改的；是否上报由固件决定，SDK 只转发
   * - 0x04 重置
     - 手机 → 设备
     - 无
     - 本阶段只用于列表型设置清空全部、天气清除数据；普通设置暂不支持；没有回应
   * - 0x05 新增
     - 手机 → 设备
     - 槽号 + 完整记录
     - 列表型；槽号由 App 指定，槽已被占用时不生效；没有回应
   * - 0x06 删除
     - 手机 → 设备
     - 槽号 + 完整记录
     - 列表型；带要删除的那条的完整内容，设备按槽号删除；没有回应
   * - 0x07 修改
     - 手机 → 设备
     - 槽号 + 完整记录
     - 列表型；必须带完整内容，槽是空的时不生效；没有回应
   * - 0x08～0xFF
     - —
     - 保留
     - 以后新增操作接在后面，不插入、不重排

.. _cmd-02-section-3:

交互规则
--------

1. 写操作没有回应：设置、新增、删除、修改、重置发出后，设备只回 L1 ACK。L1 ACK 只表示设备收到了，不表示设置成功；真正生效以通知为准。手机收到 L1 ACK 就可以发下一条。参数不合法、设备不支持时设备不生效，也不会有对应的通知。
2. 读取：设备回读取回应，带当前值。设备不支持、读不出来时不回应，手机等到超时（默认 5 秒）按失败处理。
3. 一次只操作一个 key，不支持一条命令批量设置或读取。
4. 通知：设备上的设置有变更就上报当前值（列表型为变更类型 + 单条记录），不区分是手机设置的还是手表上改的，全局只有这一种变更通知。是否上报、什么时候上报由固件决定；SDK 不判断，只监听并转发给上层。手机只回 L1 ACK，不回 L2；只在登录成功后上报。
5. 生效时间段：自动监测、告警、间隔提醒都带"开始时 + 开始分 + 结束时 + 结束分"4 字节，开始等于结束（如 00 00 00 00）表示全天，支持跨天（如 22:00～06:00）。
6. 列表型设置（闹钟、通讯录、SOS 联系人）：设备内部为固定槽位，槽号由 App 指定，一次只操作一条。新增 = 槽号 + 完整记录，槽已被占用时不生效；修改 = 槽号 + 完整记录，必须带完整内容；删除 = 槽号 + 完整记录，设备按槽号删除；清空全部 = 重置。读取返回完整列表：容量 1B + 个数 1B + [记录长度 1B + 单条记录] × 个数。通知只带变更的那一条：变更类型 1B（05 新增，06 删除，07 修改，04 清空）+ 单条记录（清空时没有）。整表覆盖由 SDK 封装为"重置 + 逐条新增"。通讯录容量大，读取分页：读取带起始槽号，回应多带"下一个起始槽号"，等于容量表示已读完。
7. 扩展：以后给设置项加字段只能加在末尾。接收方遇到多出的字节直接忽略；读取回应、通知里缺少的字段视为设备不支持；设置时没带的末尾字段保持原值，设备不得重置为默认值。
8. 健康监测（0x40～0x5F）每种数据固定占 4 个连续的 key：自动监测、告警、单位、保留，没有的项空着。心率 0x40、HRV 0x44、血压 0x48、血糖 0x4C、血氧 0x50、压力 0x54、体温 0x58、热应激 0x5C。单位只影响手表上的显示，协议里的数据和告警阈值固定用协议规定的单位，不随单位设置变；手表上的天气温度也按体温单位显示。
9. 设备控制（0x34）：只支持设置，动作 01 重启、02 关机、03 恢复出厂设置。设备回 L1 ACK 后约 1 秒执行并断开，没有 L2 回应和通知；App 5 秒内没看到断开按失败处理。恢复出厂后手表清除绑定，App 把设备当作已解绑。

具体命令
--------

* "具体的命令"一列为完整的 L2 数据（十六进制，大端序），可直接对照抓包。
