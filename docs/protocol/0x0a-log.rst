通用说明
------------------------------------------------------------------------------------------------------------------------

1.1 命令格式（L2 层，不含 L1 帧头）

.. list-table::
   :header-rows: 1
   :widths: auto

   * - 字段
     - 长度
     - 取值
     - 说明
   * - L2 Header
     - 2B
     - 0A 00
     - Command = 0x0A 日志命令，Version = 0，Reserve = 0
   * - Key
     - 1B
     - 见 1.2
     - 每种消息一个 key
   * - v-length
     - 2B
     - Value 的字节数
     - 不含 L2 Header、Key、v-length 本身
   * - Value
     - 可变
     - 见第 2 节
     - 只有 0x03 带数据

示例：打开日志
L2 Header | Key | v-length
0A 00 | 01 | 00 00
1.2 Key 列表

.. list-table::
   :header-rows: 1
   :widths: auto

   * - Key
     - 名称
     - 方向
     - Value
     - 说明
   * - 0x01
     - 打开日志
     - 手机 → 手表
     - 无
     - 没有 L2 回应
   * - 0x02
     - 关闭日志
     - 手机 → 手表
     - 无
     - 没有 L2 回应
   * - 0x03
     - 日志发送
     - 手表 → 手机
     - 日志内容 0～499 字节
     - 打开期间持续发
   * - 0x04～0xFF
     - 保留
     - —
     - —
     - \ 

1.3 交互规则
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

1. 打开、关闭都没有 L2 回应，只有 L1 ACK。打开后一直收不到 0x03，说明固件不支持或当前没有日志，SDK 不报错。
2. 日志内容由固件原样输出（文本或固件自己的格式），SDK 不解析、不拆行，按收到的顺序把原始字节追加到文件，文件按"设备 + 打开时间"命名，路径交给 App。
3. 一帧最多 499 字节，可以带多行；一行太长时固件可以拆到多帧，SDK 只管按顺序拼接。
4. 断开连接后手表自动关闭日志，不保存"已打开"的状态；重连后要再发 0x01。
5. 日志会占用蓝牙带宽、增加功耗，量产 App 不打开，只在 Demo 调试页和联调时用。打开期间其它命令照常收发。
6. 关闭后手表不再发 0x03；关闭前已经在路上的帧，SDK 照常写进文件。

1.4 表格说明

* "具体的命令"一列为完整的 L2 数据（十六进制，大端序），可直接对照抓包。按字段分颜色：

配色：0A 00 灰色：L2 Header 03 红色加粗：Key 00 12 灰色：v-length 5B 49 5D 绿色加粗：Value

* 完整过程见"交互示例"工作表；需要固件确认的问题见"待确认"工作表。
